Row 19 evidence: make the fake-ip fixture safe under parallel test execution

Scope
------
Changed tests/common/mod.rs and tests/ha_addresses.rs. tests/fake_ip.rs required
no source change; it consumes the common fixture and was covered by the same
verification runs.

Before
------
- Historical clean-HEAD runs were intermittently failing with ETXTBSY.
- The concurrent reproduction ran 25 iterations, launching two fake_ip binaries
  and one ha_addresses binary per iteration: 75 total test-binary runs.
- Before the fix, 10 of 25 iterations reported ETXTBSY.
- Historical evidence also recorded 3 failures in 10 ha_addresses-only runs and
  ETXTBSY failures in the full test gate.
- The old direct-write stress demo observed ETXTBSY during concurrent writes
  and executions: 28,777 failures in 37,898 executions and 295,443 failures
  in 1,313,653 writes.

Race-window analysis
--------------------
Writing an executable script in the test process leaves a writable file
descriptor in the process fd table. A concurrent Command child can be cloned
while that descriptor is open. CLOEXEC closes the inherited descriptor only
when the child reaches execve, so the child can keep the script inode
writable after the writer itself has closed its descriptor. A later execve of
the script then fails with ETXTBSY.

The isolated C proof reproduced this mechanism after the writer closed its own
descriptor. It failed with ETXTBSY both when writing directly to the final path
and when writing a temporary path followed by rename; rename follows the inode
and therefore does not eliminate the inherited-descriptor window.

Fix
---
- write_executable now delegates publication to a dedicated writer subprocess;
- the writer receives script contents through stdin;
- it writes a unique temporary file, chmods it, and renames it into place;
- the parent waits for the writer to exit before the fixture can execute the
  script.

This keeps writable script descriptors out of the test process fd table, so
parallel Command children cannot inherit them. The awaited subprocess and
atomic rename ensure that the final path is published only after complete
script contents are available.

After
-----
- Adversarial reproduction: 75 total test-binary runs across 25 iterations,
  0 iterations with ETXTBSY, and 0 iterations with test failures.
- Five consecutive default `cargo test --locked` runs all exited 0.
- Every run had identical per-target counts:
  - lib: 213 passed
  - bin: 0
  - fake_ip: 4
  - ha_addresses: 8
  - ha_hooks: 3
  - ha_mode: 12
  - doc: 0
  - total: 240
- `cargo check --locked --all-targets`: exit 0.
- `cargo fmt --all -- --check`: exit 0.
- `cargo clippy --locked --all-targets --all-features`: exit 0.

Residual risk
-------------
The named row-19 scope is covered. Other test-local executable-script writers
outside the changed files should be audited separately if future failures
identify them; no such failure occurred in the five full-suite runs.
